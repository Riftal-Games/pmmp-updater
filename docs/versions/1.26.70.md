## Where this differs from #10's body

#10 was scoped on `v1.26.70-preview.22`. Against `v1.26.70-preview.23`:

- `DisconnectPacket` changes only through `DisconnectFailReason` values 151 to 158 (`Session*`). The package carries the reason as a plain int (`DisconnectPacket.php:25,45`), so there is no code change.
- `CommandBlockUpdatePacket` also gains `Last Output Is Raw Message`, a bool after `Execute On First Tick`.
- The `LevelSoundEvent` renumber does not reach our wire. `LevelSoundEventPacket` sends a `SoundEventIdentifier`, which is `type: string`, and the package reads a string (`LevelSoundEventPacket.php:68`). No schema references `LevelSoundEvent` by number. The notes also disagree on the numbers (below); the schema gives `convert_to_frostbite` 614, `convert_to_zombie` 615, `crack` 616.

## Encoding conventions used below

Read from the package, which works against the 2225 client:
- A field not in `required` and with no `default` is a presence-prefixed optional: `PlaySoundPacket.php:77-78`, `types/ServerJoinInformation.php:36-38`.
- A field not in `required` but with a `default` is written plainly: `Message` and `Parameter List` in `TextPacket.php:141-144`, `Parameters` in `CommandOutputPacket.php:62-64`. Bools of that shape are plain bools: `Allow aim assist` (`ClientCameraAimAssistPacketPayload.json:18-23`) at `ClientCameraAimAssistPacket.php:50`, `loadFromJson` (`CameraInstruction__SplineInstruction.json:17-22`) at `types/camera/CameraSplineInstruction.php:89`, and `DepthTest`, `ShowBackface`, `ShowTextBackface` (`TextDataPayload.json`, only `Text` required) at `types/shape/PrimitiveShapeTextPayload.php:58-60`. `/codegen` does not know this rule and drafts such a field as optional.
- An enum without `Enum-as-Value` has no single encoding in the package:
  - int32 enums of that shape are read as the enum's string name: `operation` at `types/AttributeValueBool.php:51`, `Version` at `CommandRequestPacket.php:46`, `Output Type` at `CommandOutputPacket.php:44`, `FOV Ease Type` at `types/camera/CameraFovInstruction.php:42`. No package read contradicts this.
  - uint8 enums of that shape are read both ways. As a string: `Swing Source` (`ActorSwingSource`, `AnimatePacketPayload.json:34-38`) at `AnimatePacket.php:53`, `CloseReason` (`DataDrivenScreenClosedReason`) at `ServerboundDataDrivenScreenClosedPacket.php:44`. As a byte: `Playback Type` (`AudioContentPlaybackType`, `ClientboundPlayAudioContentPacketPayload.json:18-21`) at `ClientboundPlayAudioContentPacket.php:62`. The schemas do not tell the two apart: each enum carries `x-enum-binary-value`, and the field has `x-underlying-type: uint8` and no `x-serialization-options`.
  - Developer note `r26u0/bug_1526431` says a missing `Enum-as-Value` trait changed `TextPacket`'s bytes, not what they became. `/codegen` drafts every such enum as a string (`tools/codegen/generate.js:258`, `:311`).
  - A new uint8 enum of this shape, with no package read of that same enum, is an open question for #5 (question 3).

Field order is `x-ordinal-index`. Schemas are in the docs cache, `%LOCALAPPDATA%\pmmp-updater\cache\mojang-docs\v1.26.70-preview.23\json\<Type>.json`.
